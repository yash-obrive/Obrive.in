      </li>
      <li>
        A <StyledText>本地 VR 应用</StyledText>，为具有先进空间跟踪的头戴设备而建。

    Web VR 版本提供了无缝的可访问性：利益相关者可以在多种设备上即时加入。与此同时，原生应用提供了惊艳的视觉效果和精准的交互体验。 <br />
    两者都印象深刻——但原因不同。那种平衡激发了一段企业级决策的旅程
  </WhyItWorkedItem>

<WhyItWorkedSection title="何时选择 Web VR——何时选择原生方式">
  <WhyItWorkedItem>
    <StyledText>Web VR 在以下情况下表现出色：</StyledText>
    <br />
    <ul>
      <li> 快速上市是关键——通过链接或二维码分享，你就上线了。</li>
      <li> 你需要跨平台覆盖而无需开发负担。</li>
      <li>
        你瞄准轻量级虚拟现实：产品预览、演练、频繁更新。
      </li>
    </ul>
    <br />
    <StyledText>但是原生应用 VR 在以下情况下获胜：</StyledText>
    <br />
    <ul>
      <li>
        你需要现实感——高级追踪、SLAM 或高保真交互。
      </li>
      <li>
        用例需要离线稳定性、复杂环境或坚固的硬件。
      </li>
    </ul>
  </WhyItWorkedItem>
</WhyItWorkedSection>

<WhyItWorkedSection title="超越热潮：为什么两条路径都重要">
  <WhyItWorkedItem>
    Web VR 并不是要取代基于应用的 VR——它是为了降低进入门槛。你可以 <StyledText>开始沉浸式</StyledText> 使用 Web VR，然后通过强大的本地 VR 构建来加深参与度。
    <br />
    <br />
    在Obrive，我们采用双轨策略：在早期阶段部署即时网络虚拟现实，然后过渡到为可扩展企业应用定制的应用虚拟现实。
  </WhyItWorkedItem>
</WhyItWorkedSection>

<WhyItWorkedSection title="前景展望">
  <WhyItWorkedItem>
    <ul>
      <li>
        As <StyledText>WebXR标准成熟</StyledText>，更复杂的虚拟现实功能将能够在浏览器中使用。
      </li>
      <li>
        新兴的 <StyledText>5G 和边缘计算</StyledText> 将提升基于浏览器的虚拟现实的流媒体保真度。
      </li>
      <li>
        <StyledText>混合框架</StyledText> (Unity、Babylon.js) 正在模糊界限——一次构建，多平台。
      </li>
      <li>
        支持协作的“VR准备”解决方案适用于移动端、桌面端和VR——最大化覆盖范围
      </li>
    </ul>
  </WhyItWorkedItem>
</WhyItWorkedSection>

<WhyItWorkedSection title="结论：选择有意义的，而不仅仅是酷的">
  <WhyItWorkedItem>

    <br />
